이전 시도 기록 — iframe 방식은 사용자 요청과 달라 폐기됨 (2026-10-30)

사용자는 원본 사이트 삽입을 거절하고 우리 지도·우리 장비 조회 연결을 요청했다.
아래는 이전 시험 결과를 보존한 기록이며 현재 적용 방식으로 사용하면 안 된다.
현재 작업: 공식 연맹원 목록 + 개별 프로필 좌표 → 자체 Canvas 부분 지도.
검증 완료 결과는 별도 공식 API 지도 검증 기록으로 남긴다.

지도 복구 경로 검증 — 2026-10-30

확인 결과
1. 서버에서 mightpulse.com/api/map를 호출하면 403, cf-mitigated: challenge,
   text/html, Just a moment... 보안 페이지가 반환된다. API 키 오류와 구분된다.
2. 새 키의 공식 /v1/players 조회는 200. Zeras(241496933)의 UID 60611017,
   왕국1622, 좌표432/641, 영웅5명 확인. 영주 장비는 hidden=true.
3. 공식 /v1/kingdoms/1622/ranks?board=alliance_power&limit=2 및
   /v1/alliances/1622/ROK?include=info,roster도 200.
   ROK roster90명에는 좌표 필드가 없다. 개별 프로필에는 좌표가 있다.
   따라서 공식 API를 조합한 부분 지도도 가능하지만 전체 지도와 동일하지 않다.
4. 다른 origin의 localhost 페이지에 원본 /map 화면을 iframe으로 삽입하면
   현재 사용자 브라우저에서 전체 지도가 정상 로드됨을 실제 확인했다.

적용한 해결책
- 원본 화면을 그대로 삽입하는 EmbeddedKingdomMap 컴포넌트 추가.
- 기존 지도 API 성공 시 기존 Canvas 사용. 실패/timeout 시 원본 화면으로 전환.
- 영주 프로필에는 실제 UID를 전달하고, 다른 왕국 조회 시 이 UID를 전달하지 않음.
- iframe 대상은 고정 HTTPS 주소, kid/uid 검증, 제한된 sandbox 및 fullscreen.
- 원본 화면의 브랜드/유료 기능/인증을 수정하거나 우회하지 않는다.
- 지도 데이터를 추출해 우리 Canvas에 공급하는 기능은 아님.
- 삽입 화면 내 프로필 링크는 원본 서비스로 연결되며 우리 장비 조회 콜백과 연동되지 않음.
- iframe이 로드되었다는 이벤트만으로 데이터 갱신 성공을 표시하지 않는다.
- 새 탭 링크를 함께 제공한다. 외부 정책/브라우저 환경에 따라 삽입이 실패할 수 있다.
