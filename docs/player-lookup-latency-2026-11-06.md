# 영주 조회 지연 진단 및 빠른 조회 경로

## 실측과 한계

- 지도에서 장비 보기 클릭 후 기존 `/api/player` 요청 대기 약 67.94초, 화면 렌더 약 20ms. 주된 지연은 렌더링이 아니라 서버 응답 대기였다.
- MightPulse 웹 페이지의 `/api/players/{uid}` GET은 PC에서 약 0.57초. 원본 화면의 실제 Refresh도 약 2.46초에 새 `detail_updated_at`을 반환했다. 단순 브라우저 캐시만의 차이가 아니다.
- 동일 Vercel 프로젝트의 production 환경에 도메인을 연결하지 않은 진단 함수를 배포했다. 웹 GET은 200 JSON, 483ms, 영웅 5명/영주 장비 6개를 반환했다. 자체 서비스 User-Agent와 Accept만 사용했으며 API 키나 브라우저 쿠키는 보내지 않았다.
- 같은 환경에서 웹 refresh POST는 403. PC에서도 `Refresh only from the site`였다. 이 제한을 우회하지 않는다.
- 공식 `/v1/players`는 오래된 자료 갱신에 오래 걸릴 수 있다. 웹 경로와 공식 경로의 서비스 내부 차이 전체를 확인한 것은 아니며, 모든 지연을 Cloudflare나 특정 사용자 차단으로 단정할 수 없다.

## 적용 구조

1. 일반 `/api/player` 조회는 웹 GET을 먼저 시도한다. 지도 클릭은 실제 UID를 전달한다. 영주 ID는 정확히 일치하는 검색 결과로 UID를 해석한다.
2. 영웅·장비·순위·개인정보 표시 상태를 기존 화면 형식으로 변환한다. ID 불일치, 형식 변경, HTML/403, 불완전 데이터, 5초 초과 시 공식 API로 넘긴다.
3. 수동 `refresh=1`은 일반 조회 캐시를 건너뛰고 공식 API를 호출한다. 원본 웹 refresh POST를 대리 호출하지 않는다. 공식 API 자체 캐시까지 강제로 무효화하거나 게임 내 실시간 상태를 보장하지 않는다.
4. 웹 조회 캐시는 60초, 공식 조회 캐시는 5분이다. 영주 ID/UID 별칭은 확인된 응답 ID에만 연결한다. 응답의 실제 자료 시각을 보존한다.
5. 지도 선택 직후 지도에 있는 이름·좌표를 먼저 표시한다. 이전에 조회한 프로필도 표시하되 저장 정보임을 안내한다. 새 응답이 비공개 장비면 이전 공개 장비를 제거한다.
6. 갱신 실패 시 기존 화면을 유지하고 재시도를 제공한다. 다른 영주로 바꾸면 이전 요청 결과가 화면을 덮지 않게 한다.

## 재발 시 점검

- 브라우저 Network에서 클릭→요청 시작, 요청 대기, 응답→렌더를 분리 측정한다.
- `/api/player`의 `source`가 `web`인지 `official`인지 확인한다. API 키와 공급처 원문 오류 본문을 로그로 남기지 않는다.
- PC 성공만으로 운영 성공을 가정하지 않는다. Vercel 함수에서 동일 경로의 HTTP 상태·Content-Type·소요 시간을 확인한다.
- `web` 실패 시 Cloudflare HTML, JSON 오류, 응답 스키마 변경, ID 검증 실패를 구분한다. 인증이나 발신지 위장으로 제한을 우회하지 않는다.
- 확인한 장비가 잘못 매핑되면 `src/lib/server/web-player.ts`를 수정하고 합성 데이터 테스트 및 실제 두 응답의 표시 필드를 대조한다.
- `node --test "tests/*.test.mjs"`, Astro check, build 후 운영 환경에서 공개/비공개 프로필을 확인한다.

웹 GET은 문서화된 외부 API 계약이 아니므로 영구적인 사용 가능성이나 응답 속도를 보장하지 않는다. 공식 API 대체 경로를 유지한다.

## 운영 배포 확인

- 첫 영주 ID 검색 1.344초(`web`), 재조회 48ms. 다른 비공개 프로필은 692ms(`web`), 영주 장비 0개로 비공개 유지.
- 지도에서 선택한 또 다른 영주는 20.935초(`official`)였다. 이후 웹 응답은 기존 검증을 통과했다. 최초 웹 응답/실패 기록이 없어 이 건의 대체 경로 진입 원인은 확정하지 않는다. 자료의 갱신 시각이 그 사이 바뀌었으므로 사후 응답만으로 최초 상태를 추정하지 않는다.
- 별도로 발견한 개선: 정상 프로필의 영웅 장비/스킬이 빈 배열인 경우도 허용한다. 필드 누락·잘못된 형식은 계속 공식 API로 넘긴다. 이것이 위 20.935초 사례의 원인이라고 주장하지 않는다.
